# 细节审片：连续、不空、精（交付前必做）

起因（2026-09-29，某 AI 模型概念片，两条用户反馈）：

1. 「26s 和 27s 转场有点问题，一个是突兀，一个是音频也有问题」：明→暗那一刀，车间在一帧内被卸掉换成夜空，光晕、泛光、暗角同帧跳变；音乐被砍到数字静音 1.2 秒，暗底又从零硬起。
2. 「左下角的字体不够优雅……我们要注意细节来完善自己的渲染能力」：根因是字体文件少了光学字号轴，外加一串排版细节没做（typography.md）。

观众不会逐项指出问题，但每一个**断点**都会被感觉到。做法不是靠感觉，而是把细节变成**清单 + 脚本**，每次预览给用户看之前先自己过一遍。

## 三条原则

1. **连续**：画面里任何「出现 / 消失 / 参数切换」都必须是帧号的连续函数。转折处要有一个**承载物**贯穿前后（那支概念片里是最后一个句点：灯灭了它还亮着，云团从它里面长出来），而不是卸掉旧场景再挂新场景。
2. **不空**：声音里永远没有数字静音。音乐用「低通扫频 + 淡出」关灯，最后半秒送进暗房混响做尾音，暗底从尾音里渐入，第一下心跳落在转折帧。硬停本身是好手法，但要有自然衰减，不能是采样值直接归零。
3. **精**：文字是观众看得最近的东西。光学字号、字重 / 字距 / 行高、真标点、手工断行、无孤字和悬挂分隔符、不与物体相撞（typography.md §5–7）。

## 流程（每次改动后重做，先于预览交给用户）

1. **列切换点清单**。在代码里找：挂载 / 卸载条件（`f >= N`、`f < N`）、环境函数的分段点、后期参数的分支（`a ? x : y`）、相机关键帧的缓动、任何 `else`。写成表：帧号 | 变了什么 | 连续吗？不连续的要么改成连续，要么标「有意硬切」。
2. **看切换点前后各 4 帧**（`--around` 写秒数：帧号 / 30；`--diff` 再出一张与前一帧的差，看闪烁和跳帧）：

   ```bash
   rn sheet out/film-preview.mp4 --around 26.4,35.4 --span 4 -o out/seam.jpg
   rn sheet out/film-preview.mp4 --around 26.4,35.4 --span 4 --diff -o out/seam-diff.jpg
   ```

3. **画面与声音的自动审计**（`render.sh` 的每种成片模式都会自动跑，结果在 `out/audit/`；也可单独跑）：

   ```bash
   rn qa out/film.mp4 --json out/audit/qa.json              # 格式、响度、true peak、黑帧、冻帧、数字静音、电平跳变、爆音、固定帧率
   rn cuts out/film.mp4 --sheet out/audit/cuts.jpg          # 硬切清单（解码帧号），每刀前后各一帧；弱变化列为 suspects
   rn signal out/film.mp4 -o out/audit/signal.png           # 逐帧亮度 / 帧差 / 频段 / 鼓点 / 爆音曲线，找「哪里突兀」时看
   ```

   每一条要么修，要么写进项目根目录的 `qa-accept.txt` 并在交付说明里写明「有意为之」（例如开场的停顿、Snap 处的闪白）：

   ```text
   black_frames@0.2     # 开场从黑里淡入
   level_jumps@26.5     # Snap 处的重击
   ```

   `检查项@秒` 只豁免那一处，只写 `检查项` 豁免整项；FAIL 不能豁免。
4. **文字审计**：

   ```bash
   python3 <skill>/scripts/typo_lint.py storyboard.json            # 模板片；加 --fix 自动修直撇号、三个点、--、全角标点
   python3 <skill>/scripts/typo_lint.py --ts src/film/*.ts src/film/*.tsx --ignore dspace   # 电影级源码，只报告；--ignore 跳过有意为之的规则（等宽标签里刻意的双空格）
   python3 <skill>/scripts/font_check.py public/fonts               # 轴、特性、真标点字形；缺 opsz 会警告
   ```

5. **抽 4K 帧看字**：每行字完全显现的那一帧（`render.sh <项目> film-stills <帧号...>`，自动拼成 `out/stills-sheet.jpg`；也可 `rn sheet <静帧文件夹>`），检查换行、孤字、与 3D 物体的碰撞（相机漂移、画面偏移都会把物体滑到文字下面）。`rn text out/film.mp4` 读出每行字的出现时间和位置框，可核对文字有没有被截断、出现时长够不够读。
6. **交付说明里写出**：这支片有哪些有意的硬切 / 静音 / 极细字，让用户知道它们是设计过的。

## 连续性配方：明→暗的转折（可直接套用）

画面（那支概念片，第 764–830 帧）：

1. **灯光**：一个 `darkAt(f)`（smoothstep，约 1 秒）同时驱动主光、半球光、环境光、雾、面板亮度、天空、文字颜色。天空经「奶白 → 琥珀 → 夜」三段，不走灰。
2. **承载物保持发亮**：最后的句点用 HDR 发光小球（颜色 ×2.4，泛光吃得到）+ 加法混合光晕精灵，光晕在熄灯期间「点燃」（`ignite`）。
3. **卸载晚于全黑**：面板亮度先落到 0，再卸载车间 / 地板 / 太阳盘（比全黑晚约 10 帧）。天空球提前挂载，颜色 = 当前背景色，接管时不跳。
4. **新内容从承载物里长出来**：云团着色器加一个揭示半径 `uRev`（球内笔画才存在，边缘 `4·rv·(1−rv)` 的余烬色），半径 = max(小气泡, 相机距离 − 3)。相机后拉时墨迹永远在镜头前方 3 个单位，杜绝近景「火柴棍」乱象。
5. **后期参数由同一个暗度驱动**：泛光、暗角、景深范围与焦外强度都是 `mix(a, b, 暗度)`，不用 `inCloud ? a : b` 分支。
6. **相机**：推向承载物用 `sine` 或二次 inOut，到点时已减速；不要用 `expo.in`（位移全挤在最后几帧，像撞上去）。

声音：

1. 音乐尾部 1.4 秒：低通扫频（15 kHz → 1.1 kHz）+ 逐渐加深的淡出，到小节线前归零。
2. 最后半秒素材经暗房混响（`fft_conv`，RT ≈ 3.4 秒，越衰越暗）做尾音，叠在淡出之下。**不要拿下一小节续尾**（Lyria 的下一小节第一拍常是满幅重击）。
3. 暗底 drone 用 1.8 秒线性渐入，起点就在小节线上；第一下心跳落在承载物点亮那一帧，之后音量很轻；相机拉远时叠一层「空气 swell」代替 whoosh。
4. 全程电平不低于约 −35 dB；`rn qa` 的 `dead_air` 必须是 PASS（有意静音写进 `qa-accept.txt`）。

## 交付编码（最后一步，发文件之前）

起因（2026-09-29，某医疗器械品牌片）：用户「发出去是 38 秒，实际打开只有 19 秒」。容器（mvhd / tkhd / elst / stts）完全正确、macOS 也读 37.5 秒，问题在 H.264 码流和封装：

| 问题（Remotion 直出） | 后果 | `rn finish` 的处理（`render.sh` 自动做） |
|---|---|---|
| SPS VUI `fixed_frame_rate_flag=0`，`time_scale=60 / num_units_in_tick=1` | 按 VUI tick 给每帧计时的播放器 / 平台得到 60 fps → 时长减半（1125 / 60 = 18.75 秒） | 重新编码，x264 `force-cfr` → `fixed_frame_rate_flag=1`；`rn qa` 的 `fixed_frame_rate` 项检查 |
| `yuvj420p` 全范围，矩阵标 BT.601，原色 / 传递函数未标 | 不认范围标记的播放器颜色发灰或过饱和 | 按源矩阵真正转换到 BT.709 TV 范围（不只是打标签），三项标记在码流和容器里都写上 |
| moov 在文件末尾 | 网页 / 聊天软件边下边播时读不到索引 | 一律 `+faststart`；`rn qa` 的 `faststart` 项检查 |
| 音轨带 AAC 编码延迟且未补偿（elst media_time 0） | 声音整体晚 43.7 ms，卡点晚 1.3 帧 | 成片：画面 `--muted` 渲染，混音另渲 WAV，`rn finish --audio out/mix.wav`；预览：`--audio-offset -0.0437` |
| 响度不统一、AAC 编码后峰值抬升 | 平台二次压缩、削波 | −14 LUFS，**编码后**测 true peak ≤ −1 dBTP，超了自动降限幅重编音频 |
| 只有 4K | 手机 / 微信常被转码或拒收 | `rn finish 4k.mp4 -o 1080p.mp4 --height 1080 --lufs keep`（`render.sh` 对 4K 成片自动出） |

```bash
npx remotion render src/index.ts Film out/film-raw-4k.mp4 --muted                # 构图本身是 3840×2160；1080p 构图加 --scale=2
npx remotion render src/index.ts Film out/mix.wav --codec=wav --config=remotion.audio.config.ts   # 配置里不能有 CRF
rn finish out/film-raw-4k.mp4 -o out/<名字>.mp4 --audio out/mix.wav
rn finish out/<名字>.mp4 -o out/<名字>-1080p.mp4 --height 1080 --lufs keep
rn qa out/<名字>.mp4                                                                               # 任何要发出去的文件都先过这一步
```

对照色值时，解码要加 `accurate_rnd+full_chroma_int`：swscale 的快速默认会把 TV 范围解得偏暗约 2 个色阶，看起来像编码出了问题。

## 判定阈值（`rn qa` / `rn cuts`）

| 项 | 命令与检查项 | 阈值 |
|---|---|---|
| 硬切 | `rn cuts` | ffmpeg 场景分数 ≥ 0.3 记为剪点，0.15–0.3 列为 suspects（运镜、变形、叠化分数低，先看拼图再信） |
| 黑帧 | `rn qa` `black_frames` | 像素亮度阈值 0.10、持续 ≥ 0.1 秒；片头片尾的有意黑场用 `qa-accept.txt` 豁免 |
| 冻帧 | `rn qa` `frozen_frames` | −60 dB 噪声内静止 ≥ 0.5 秒 |
| 数字静音 | `rn qa` `dead_air` | ≥ 60 ms 低于 −70 dBFS（片头片尾 0.05 秒外） |
| 电平跳变 | `rn qa` `level_jumps` | 相邻 100 ms RMS 差 ≥ 15 dB 且较响的一侧 > −60 dB（设计过的重击、音效写进豁免） |
| 爆音 | `rn qa` `clicks` | 孤立的采样阶跃 > 局部 99.5 分位的 8 倍，且 > 同 50 ms 内次大阶跃的 2.5 倍 |
| 闪帧 | `rn signal` `flashes` | 亮度跳升 ≥ 0.2 并在 4 帧内回落 |

## 踩过的坑

- **光晕被面板盖掉**：`Panel3D` 的面是 `transparent` 且 `renderOrder=2`，加法混合的光晕精灵默认 0 先画，被面板盖住，直到面板卸载才「突然出现」。精灵设 `renderOrder={3}`。
- **天空球过早挂载**：它不透明，会盖住 `scene.background`，左上角冒出黑楔形。挂载时刻要早于熄灯，且颜色跟随背景色。
- **后期参数一帧跳变**：泛光 / 暗角 / 景深在同一帧从一组值切到另一组，画面「啪」一下。
- **打字进度用 `E.out`**：渐近曲线让最后一个字母比句点还晚。改线性 + `ceil`，比句点提前约 4 帧完成。
- **文字与物体相撞**：镜头漂移 + 画面偏移会把小火花滑到最后一行诗下面；让物体反向漂移相同的量。
- **音乐硬停到数字零**、**暗底从零硬起**：都会被听成故障。
- **CSS 遮罩外的内容整块消失**（某新茶饮品牌片，真杯「从上往下倒进来」时整段看不见）：`mask-image` 默认 `mask-clip: border-box`，元素盒子外溢出的子元素被裁掉。遮罩容器要把内容包在自己的盒子里（给它显式 left / top / width / height），别用全屏 `AbsoluteFill` 去罩一个画在全景坐标 x=3200 的东西。
- **笔顺遮罩漏画小部件**（某新茶饮品牌片，小人闭着的眼睛最后才「闪」出来）：细化后的骨架在小闭合形状上会出现度数 2 的假节点，「剪短毛刺」把两半都剪掉了。只剪挂在真分叉（度 ≥ 3）上的短末端；笔刷宽 = 2×局部半径 + 12，圆头才盖得住尖角。实心大块（头发）按 长度×(1+宽/60) 计时，否则两帧内整块冒出来。
- **翻转转场中间一帧全黑**：两半都转到 90° 时只剩背景；背景用进场那一面的颜色，不要用黑。
- **3D 镜头相邻帧来回跳**（某 3D 科普片 v1）：不是运镜，是 `ThreeCanvas` 在 CSS 缩放的容器里挂载、量错尺寸（见 cinematic.md「Three.js 规则」第一条）。验证：连续渲 300+ 帧，取固定物体边缘的 x 坐标，应单调平滑；忽大忽小就是这个坑。


## 旁白尾巴杂音（2026-09-30，用户：「10s 之后中间有什么声音」）

MiMo 偶尔在一句话说完后再「嘟囔」半秒（whisper 单听整句常常漏掉，混进成片里却听得出来；MiMo 回读的「差异」里会多出一串乱字母，如 `('', 'alakavas')`）。每批配音合成后跑：

```bash
python3 <skill>/scripts/vo_tailcheck.py <音频目录> <narration.json>   # TAIL = 最后一个真词之后还有 > -32 dB 的声音或多出来的词
```

TAIL 的拍删掉重合成；「1st / 30%」这类数字写法、品牌名被拆开会误报，逐词看一眼即可。成片再把整条混音用 whisper 转写一遍，确认没有多出来的词。
